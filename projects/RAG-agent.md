# 基于 RAG 的多模态电商智能导购 Agent

## 项目定位

该项目面向电商导购场景。目标不是让大模型凭参数记忆回答商品问题，而是将商品资料组织为可检索知识库，在回答前召回与当前需求相关的商品信息，并通过 Agent 调用检索与业务工具。

> 当前页面先沉淀系统设计与工程重点，后续将随着项目迭代补充接口示例、评测数据和运行截图。

## 要解决的问题

- 商品属性、说明文本和图片信息分散，直接检索难以覆盖多种表达方式。
- 用户通常通过多轮对话逐步补充预算、用途和偏好，需要保留上下文。
- 推荐结果需要说明依据，降低“模型凭空推荐”的风险。
- 检索、推理和业务接口需要清晰分层，便于调试和替换组件。

## 技术栈

`FastAPI` · `RAG` · `向量数据库` · `多模态检索` · `Agent 工具调用`

## 系统流程

1. 清洗商品标题、属性、详情文本和图片描述，构建统一商品文档。
2. 对文档分块并生成向量，写入向量数据库，同时保存商品 ID 等元数据。
3. 根据用户当前问题和会话约束执行召回与过滤。
4. Agent 按任务需要调用商品检索、详情查询等工具。
5. 将检索证据交给模型生成推荐结果，并输出可追溯的推荐理由。

## 工程亮点

### 商品知识库构建

以商品 ID 连接文本、属性和图片相关信息。元数据过滤与向量相似度召回分工明确，方便处理品牌、类目、价格区间等硬约束。

### 检索增强问答

生成答案前先检索商品证据，并限制回答围绕召回内容展开。该流程有助于减少商品参数幻觉，也便于定位错误来自召回还是生成。

### 多轮对话与工具调用

把用户的预算、用途和偏好整理为会话状态。Agent 负责判断何时追问、何时检索以及何时查询商品详情，避免把全部逻辑压进单个提示词。

### 推荐解释

推荐理由绑定用户约束与商品证据，说明“为什么适合”，而不是只返回商品列表。
