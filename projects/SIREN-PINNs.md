# 基于 SIREN 与物理先验的液体表面张力智能实验系统

这是一个面向大学物理实验的 AI 测量系统：用户上传激光衍射图像，系统完成条纹定位、像素—厘米标定、表面张力计算和结果可视化，并通过本地知识库辅助解释实验原理与误差来源。

[查看项目源码](https://github.com/WHUTcjh-2024/SIREN) · 技术方向：`SIREN` `物理先验` `计算机视觉` `FastAPI` `Vue 3`

![液体表面张力智能实验系统首页](/images/projects/siren/home.png)

_系统把预约测验、图像采集、数据处理、物理计算与实验答疑组织为完整实验流程。_

## 为什么要做这个系统

液体表面张力实验需要读取中央条纹、正负一级条纹与标尺位置，再根据毛细波色散关系计算结果。人工测量存在几个问题：

- 像素级取整和人工选点会把定位误差传递到最终物理量；
- 曝光、背景纹理和无关亮区可能干扰简单峰值检测；
- 标尺 OCR 可能把 `0/O`、`1/I/l` 混淆，单个错误刻度就会破坏尺度换算；
- 只输出一个数值无法判断结果是否可靠，需要同时暴露拟合与标定质量；
- 学生完成测量后仍需要理解公式、误差和操作步骤。

因此系统采用“传统图像处理给初值 + 神经隐式表示细化 + 物理计算 + RAG 答疑”的混合方案，而不是端到端黑盒回归。

## 端到端处理链路

```text
实验图像
   │
   ├── OpenCV：ROI、颜色响应、稳健一维光强剖面
   │        └── 峰值显著性 + 三峰几何对称性 → 初始条纹位置
   │
   ├── EasyOCR：多预处理、多尺度标尺识别
   │        └── 几何一致性筛选 → 像素到厘米映射
   │
   ├── SIREN：无量纲坐标上的连续光强拟合
   │        └── 数据项 + 二阶导平滑 + 弱对称约束
   │
   ├── 稠密查询 + 抛物线插值 → 小数像素位置
   │
   └── 毛细波色散关系 → 表面张力、相对误差与质量指标
```

后端为每次分析创建独立 `runId` 和输出目录，返回灰度图、标注图、光强曲线、条纹坐标、标尺锚点、被拒绝锚点、SIREN 拟合 RMSE 与标定 RMSE。前端继续调用物理计算和多组数据拟合接口，形成从图片到实验结论的闭环。

## 核心算法一：为什么先做传统 CV，再使用 SIREN

系统首先从图像中构造一维光强剖面，经高斯平滑和背景估计后寻找候选峰。候选并不是按亮度直接取前三个，而是综合峰值强度、间距和正负一级关于中央峰的几何对称性选择三元组。

传统方法给出的初值可解释、速度快，也能把 SIREN 的拟合范围限制在可信区域。神经模型只负责局部细化；如果最终极值相对初值漂移超过允许范围，系统会回退到初值，防止模型跳到相邻级次或无关亮区。

![衍射条纹自动定位结果](/images/projects/siren/annotated-result.png)

_分析结果同时标出中央条纹与正负一级条纹。输出小数像素坐标只是亚像素估计方法，真实精度仍需要标定实验验证。_

### 为什么不直接用 YOLO 或端到端 CNN 回归坐标

当前真实标注图像数量有限，而物理结构和条纹几何关系非常明确。端到端网络需要大量带坐标真值的数据，还可能在分布外图片上给出缺乏依据的结果。混合方案把搜索范围、几何关系和最大漂移写进确定性代码，训练数据需求更低，失败时也更容易定位原因。

### 为什么不只用 `find_peaks`、Gaussian 或样条

在信噪比高、峰形稳定的图片上，`find_peaks`、局部 Gaussian 或样条更简单，也应该保留为 baseline。SIREN 的价值在于把复杂周期信号表示为连续函数，可以在任意密度坐标上查询、自动求导，并自然加入全局平滑和对称约束。

是否真正优于传统方法不能由“模型更复杂”推断，必须比较定位 MAE、重复性、失败率和耗时。当前项目实现了完整方法和阶段性对比，但尚未建立足够大的亚像素真值数据集。

## 核心算法二：SIREN 连续光强表示

SIREN 使用正弦激活：

$$
\phi_i(x)=\sin\left(\omega_0(W_ix+b_i)\right)
$$

与 ReLU MLP 相比，正弦网络更适合表示高频、周期性的衍射信号。系统学习连续函数 $I(y)$，训练完成后在高密度坐标上查询局部极值，再用三点抛物线插值细化位置，因此最终定位不受整数像素网格限制。

SIREN 对初始化比较敏感。项目为首层和后续层使用与频率相关的初始化，并专门测试第一次反向传播能否让前层获得非零梯度，避免输出层错误初始化导致梯度被截断。

### 为什么要把像素坐标无量纲化

不同图像的分辨率和裁剪范围可能差异很大。系统使用：

$$
\hat y=\frac{y-y_{mid}}{d}
$$

其中 $y_{mid}$ 是正负一级条纹的中点，$d$ 是平均一级条纹间距。转换后中央光轴附近约为 0，一级条纹约为 $\pm1$，不同分辨率图片进入模型后的尺度更一致，对称约束 $I(\hat y)\approx I(-\hat y)$ 也获得了明确的几何意义。

## 核心算法三：“PINN”约束到底是什么

训练目标由三部分组成：

$$
\mathcal{L}=\mathcal{L}_{data}
+\lambda_s\mathbb{E}\left[\left(I''(y)\right)^2\right]
+\lambda_{sym}\mathbb{E}\left[\left(I(y)-I(-y)\right)^2\right]
$$

- 数据项让模型拟合观测光强；
- 二阶导项抑制不合理的高频抖动；
- 弱对称项利用中央条纹两侧近似对称的先验，但保持较低权重，避免抹掉真实不对称。

::: warning 方法定义
这里采用的是“物理先验约束的神经隐式拟合”：使用平滑性和近似对称性约束，但不涉及完整控制方程的求解，因此与通用 PDE PINN 求解器的目标不同。
:::

## 标尺标定：为什么不能直接相信 OCR

EasyOCR 只负责提供候选文字和位置，系统还执行：

- 裁剪标尺区域并旋转到便于识别的方向；
- 对原图、反色 CLAHE 和 Gamma 图进行多轮识别；
- 对小图放大，提高刻度字符可辨识度；
- 修正 `O/Q → 0`、`I/l/| → 1` 等常见混淆；
- 按匹配优先级、位置和置信度对多轮结果去重；
- 从锚点对构造候选直线，利用几何残差筛选内点；
- 返回被拒绝锚点、$R^2$ 和标定 RMSE，允许人工复核。

这比“OCR 识别到数字后直接线性拟合”更稳健，但推断缺失刻度仍可能传播错误。更严格的系统应降低推断点权重，并在锚点不足或不确定度过高时拒绝自动计算。

## 从条纹距离到表面张力

标定后，系统将像素距离转换为厘米，通过实验几何关系计算波数 $k$，再使用 Kelvin 毛细波关系：

$$
\sigma=\frac{\rho\omega^2}{k^3},\qquad \omega=2\pi f
$$

前端既支持单组参数计算，也支持多组 $(k,f)$ 数据拟合，并返回拟合斜率、$R^2$、表面张力与相对误差。

![实验数据处理与物理计算页面](/images/projects/siren/data-processing.png)

_计算页面把公式、输入量和拟合流程放在同一界面，方便检查单位与数据来源。_

## 后端为什么使用 FastAPI

路由只处理 HTTP transport，`DiffractionAnalysisService` 管理上传文件生命周期、运行目录和响应序列化，SIREN、标定与计算模块保留纯 Python 接口。这样算法可以被 API、CLI、测试或未来任务队列复用，不会与 Web 框架绑定。

OCR、PyTorch 训练和图片处理属于 CPU/GPU 密集任务，不能因为接口写成 `async def` 就直接在事件循环中执行。当前实现将同步重任务移出主事件循环；生产化则应使用任务队列和独立 Worker，快速返回 `task_id`，并对 GPU 并发设置上限。

### 为什么会话先存 JSON，而不是数据库

当前是单机实验演示，数据结构简单、规模小。本地 JSON 降低部署复杂度，写入时先生成临时文件再原子替换，减少中断造成半文件的风险；`SessionStore` 抽象也让未来替换实现更容易。

它不支持跨实例共享、复杂事务和可靠并发控制。进入多实例部署后会改为 Redis 或 PostgreSQL，并增加用户鉴权、版本号和幂等控制。

## RAG 实验助手：为什么使用 TF-IDF

知识库由几十篇领域 Markdown 组成，包含实验原理、操作指南、误差分析和常见问题。当前使用字符级 2～4 gram TF-IDF：

- 不依赖中文分词或在线 Embedding 服务；
- 启动时即可完成索引，部署和调试成本低；
- 对“表面张力”“衍射条纹”等明确术语具有较好可解释性。

缺点是对字面不同但语义相近的问题召回较弱。知识库扩大后，我会升级为 BM25/关键词 + Embedding 的混合召回并增加 Reranker，而不是为了使用向量数据库而提前增加基础设施。

当前能力应准确称为“带多轮上下文和 SSE 的 RAG 实验助手”：它没有工具调用、任务规划和循环执行，不能包装成自主 Agent。

## 测试与质量指标

系统输出的不只是最终表面张力，还包括：

- `sirenFitRmse`：连续模型对归一化局部光强的拟合误差；
- `calibrationRmseCm`：标尺锚点在线性映射下的厘米残差；
- `rulerMapping.rSquared`：标尺映射的线性拟合质量；
- 初始峰、最终峰、像素间距、厘米间距和 `runId`。

本次整理博客时重新执行了当前仓库测试：后端 **11 项 Pytest**、前端 **1 项 Vitest** 全部通过，前端生产构建成功。测试覆盖 API 校验、表面张力计算、$3/2$ 色散斜率恢复、OCR 几何异常点剔除、对称三峰选择、SIREN 首次反向传播、会话路径安全和状态持久化。

## 当前边界与后续改进

当前系统已经实现亚像素位置估计与物理先验约束拟合，但真实测量精度仍需要更完整的标定数据验证。后续工作包括：

1. 建立 30～100 张带人工复核坐标或精密位移台真值的图像集；
2. 对比 `find_peaks`、Gaussian、样条和 SIREN 的定位 MAE、方差、失败率与耗时；
3. 为每次运行记录输入哈希、代码版本、依赖版本和模型配置；
4. 将图片分析改为任务队列 + Worker，增加超时、重试和资源隔离；
5. 统一 API 错误结构，补充鉴权、限流、结构化日志和 OpenTelemetry；
6. 建立 RAG 问题集，评估 Recall@K、引用正确率和拒答准确率。
