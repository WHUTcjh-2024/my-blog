# 序列建模实践：RNN、LSTM 与 GRU

## 为什么需要RNN

传统神经网络的输入长度是固定的，但现实中很多数据是变长的序列——文本、语音、时间序列等。而且序列的顺序很重要，"我打了他"和"他打了我"意思完全不同。

RNN就是为了解决这类问题而设计的。

## 基本原理

RNN的核心是**记忆机制**。处理序列时，网络会维护一个隐藏状态，每处理一个元素就更新一次，把新信息和之前的信息融合起来。

另一个设计是**参数共享**：不管序列多长，所有位置都用同一套参数。这样既减少了参数量，又能处理任意长度的序列。

处理过程很简单：从左到右逐个处理，每一步根据当前输入和上一步的记忆更新隐藏状态，然后产生输出。

## 代码实现

### 基本RNN

```python
import torch
import torch.nn as nn

class RNN(nn.Module):
    def __init__(self, input_size, hidden_size, output_size):
        super().__init__()
        self.hidden_size = hidden_size
        self.W_xh = nn.Linear(input_size, hidden_size)
        self.W_hh = nn.Linear(hidden_size, hidden_size, bias=False)
        self.W_hy = nn.Linear(hidden_size, output_size)

    def forward(self, x, h_prev=None):
        batch_size, seq_len, _ = x.size()
        if h_prev is None:
            h_prev = torch.zeros(batch_size, self.hidden_size, device=x.device)

        outputs = []
        h_t = h_prev
        for t in range(seq_len):
            x_t = x[:, t, :]
            h_t = torch.tanh(self.W_xh(x_t) + self.W_hh(h_t))
            y_t = self.W_hy(h_t)
            outputs.append(y_t.unsqueeze(1))

        return torch.cat(outputs, dim=1), h_t
```

### 文本分类

做分类时，只需要最后一个时间步的输出，因为它包含了整个序列的信息。

```python
class RNNClassifier(nn.Module):
    def __init__(self, vocab_size, embed_size, hidden_size, num_classes):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_size)
        self.rnn = nn.RNN(embed_size, hidden_size, batch_first=True)
        self.fc = nn.Linear(hidden_size, num_classes)

    def forward(self, x):
        embedded = self.embedding(x)
        output, hidden = self.rnn(embedded)
        return self.fc(output[:, -1, :])
```

### 语言模型

语言模型的任务是预测下一个词。给定前面的词，输出下一个词的概率分布。

```python
class RNNLM(nn.Module):
    def __init__(self, vocab_size, embed_size, hidden_size):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_size)
        self.rnn = nn.RNN(embed_size, hidden_size, batch_first=True)
        self.fc = nn.Linear(hidden_size, vocab_size)

    def forward(self, x, hidden=None):
        embedded = self.embedding(x)
        output, hidden = self.rnn(embedded, hidden)
        return self.fc(output), hidden

    def generate(self, start_token, max_len, temperature=1.0):
        self.eval()
        generated = [start_token]
        input_token = torch.tensor([[start_token]])
        hidden = None

        with torch.no_grad():
            for _ in range(max_len):
                output, hidden = self.rnn(self.embedding(input_token), hidden)
                logits = self.fc(output[:, -1, :]) / temperature
                probs = torch.softmax(logits, dim=-1)
                next_token = torch.multinomial(probs, 1).item()
                generated.append(next_token)
                input_token = torch.tensor([[next_token]])

        return generated
```

## 训练中的问题

### 梯度消失

当序列很长时，梯度在反向传播过程中会指数级衰减，导致网络学不到长距离的依赖。

比如句子"The cat, which sat on the mat, was sleeping"，网络需要记住"cat"才能正确预测"was"，但序列太长时前面的信息就丢失了。

### 梯度爆炸

另一个问题是梯度爆炸，梯度变得太大导致训练不稳定。解决方法是梯度裁剪，把梯度限制在一定范围内。

## LSTM

为了解决梯度消失问题，LSTM（长短期记忆网络）在1997年被提出。它引入了细胞状态和门控机制。

LSTM有三个门：

  **遗忘门**：决定丢弃哪些旧信息

  **输入门**：决定存入哪些新信息

  **输出门**：决定输出哪些信息


```python
class LSTM(nn.Module):
    def __init__(self, input_size, hidden_size, num_layers=1, dropout=0):
        super().__init__()
        self.lstm = nn.LSTM(
            input_size, hidden_size, num_layers,
            dropout=dropout if num_layers > 1 else 0,
            batch_first=True
        )

    def forward(self, x, hidden=None):
        return self.lstm(x, hidden)
```

## GRU

GRU（门控循环单元）是LSTM的简化版本，把三个门简化成两个：

**重置门**：控制新输入和旧记忆的结合方式

**更新门**：控制保留多少旧记忆

参数更少，训练更快，效果和LSTM差不多。

```python
class GRU(nn.Module):
    def __init__(self, input_size, hidden_size, num_layers=1, dropout=0):
        super().__init__()
        self.gru = nn.GRU(
            input_size, hidden_size, num_layers,
            dropout=dropout if num_layers > 1 else 0,
            batch_first=True
        )

    def forward(self, x, hidden=None):
        return self.gru(x, hidden)
```

## 应用场景

- **自然语言处理**：语言模型、机器翻译、情感分析、命名实体识别
- **语音处理**：语音识别、说话人识别
- **时间序列**：股票预测、天气预报、异常检测
- **其他**：音乐生成、手写识别

## 局限性

RNN有几个明显的缺点：

1. **长距离依赖**：LSTM和GRU有改善，但仍有极限
2. **无法并行**：必须按顺序处理，训练速度慢
3. **梯度问题**：需要特殊技巧来稳定训练

正因为这些限制，Transformer架构逐渐取代了RNN。不过RNN的思想仍然是理解序列模型的重要基础。

## 工程价值

1. **解决什么问题：** RNN 系列模型按时间步维护隐藏状态，用于表达顺序信息和局部时间依赖。
2. **适合场景：** 序列较短、需要流式逐步处理，或部署资源有限的时间序列与文本基线。
3. **不适合场景：** 超长上下文、大规模并行训练和强长距离依赖任务通常更适合 Transformer 类架构。
4. **PyTorch 常见坑：** `batch_first` 设置不一致、隐藏状态维度错误、变长序列未打包，以及未使用梯度裁剪导致训练不稳定。
5. **项目联系：** 多轮 Agent 的状态管理与序列建模目标相关，但实际 RAG Agent 更依赖 Transformer 和显式会话状态。
